## El Error del Billón de Dólares

En 1965, el científico de la computación Sir Tony Hoare introdujo el concepto de la "referencia nula" (`null`) al diseñar el lenguaje ALGOL W. Décadas después, él mismo se disculpó públicamente llamándolo su "error del billón de dólares", porque ha causado incontables caídas de sistemas, vulnerabilidades y horas de depuración en lenguajes como Java y C++.

El famoso **`NullPointerException` (NPE)** ocurre cuando intentas interactuar con algo que creías que existía, pero en realidad está vacío (`null`). Imagina intentar encender un auto, pero el motor literalmente no existe dentro del chasis.

Kotlin fue diseñado desde cero para solucionar este problema de raíz.

## Las Cajas: `val` vs `var`

En Kotlin, puedes imaginar que las variables son cajas donde guardas datos. Hay dos tipos fundamentales de cajas:

### La caja abierta: `var` (Variable)
Es una caja normal. Puedes meter un dato, sacarlo, y meter otro dato diferente en cualquier momento. Su contenido puede mutar o variar.

```kotlin
var age = 25
age = 26 // Perfecto, podemos cambiar el contenido.
```

### La caja sellada con cinta: `val` (Value)
Es una caja donde guardas un dato y **la sellas**. Una vez que le asignas un valor, no puedes cambiar la caja para que apunte a otro objeto. Esto se conoce como una variable de **Solo Lectura** (*Read-Only*).

```kotlin
val username = "jesusdmedinac"
username = "guest" // ❌ ERROR DE COMPILACIÓN: Val cannot be reassigned.
```

<Aside type="important">
**¿Es `val` verdaderamente Inmutable?** No. 

En la teoría pura de Kotlin, `val` significa *Solo Lectura*. Esto significa dos cosas:
1. La caja en sí no se puede reasignar, pero si dentro de la caja guardaste un objeto mutable (como una lista), puedes seguir modificando sus elementos internos.
2. Una propiedad `val` puede tener un **Custom Getter**. Bajo el capó (en el bytecode de Java), una propiedad `val` se compila como una función (un método `get()`). Esto significa que puedes programarla para que devuelva un valor distinto cada vez que la llamas (por ejemplo, `val horaActual get() = ...`), por lo que no siempre es estrictamente constante.
</Aside>

## Null Safety: Agitando las cajas transparentes

El sistema de tipos de Kotlin distingue entre referencias que **pueden ser nulas** (cajas que podrían estar vacías) y las que **no pueden serlo** (cajas que te garantizan que tienen algo dentro).

Para decirle a Kotlin que una caja *podría* contener `null`, le agregamos un signo de interrogación `?` al tipo:

```kotlin
var name: String = "Jesus"
name = null // ❌ ERROR: Null can not be a value of a non-null type String

var nullableName: String? = "Daniel"
nullableName = null // ✅ Perfecto, el tipo es String?
```

### Operadores Seguros

Si tienes una caja que podría estar vacía (`String?`), Kotlin **no te dejará** usar su contenido directamente, porque si estuviera vacía, explotaría el programa. Tienes que agitarla primero.

La forma más directa y segura de hacerlo, muy conocida por los programadores de Java, es usar un bloque condicional clásico: verificar si la caja no es nula antes de intentar abrirla.

```kotlin
if (nullableName != null) {
    // Aquí adentro, Kotlin automáticamente promueve nullableName a un tipo seguro (String normal)
    // porque ya demostraste matemáticamente que no es nulo. A esto se le llama Smart Cast.
    println(nullableName.length)
}
```

## Detrás de cámaras: Tipos de Plataforma (`String!`)

Hay un secreto oscuro en el que Kotlin no te puede proteger mágicamente. Dado que Kotlin corre sobre la JVM, es **altamente interoperable con Java**. Puedes llamar a librerías escritas en Java directamente desde Kotlin.

El problema radica en que Java **no tiene null safety estricto** y la nulabilidad de sus retornos no siempre se conoce en tiempo de compilación. Cuando Kotlin recibe un objeto desde Java, a menudo no sabe si es seguro (`String`) o si podría ser nulo (`String?`).

Para resolver esto sin volver locos a los desarrolladores llenando el código de errores, Kotlin introduce los **Platform Types** (representados visualmente en el IDE con un `!` al final, como `String!`). 

<Aside type="caution">
Un Platform Type (`String!`) significa: *"Este valor viene de Java y no sé su nulabilidad en tiempo de compilación. Relajaré mis reglas y confiaré en ti. Si te equivocas, lanzaré un `NullPointerException`"*. 

**Aviso importante:** Nunca intentes escribir un tipo como `val nombre: String!` manualmente en tu código. Es puramente una notación visual del compilador para avisarte del peligro; no es sintaxis válida de Kotlin.
</Aside>

### Instrucciones Paso a Paso

En la Lección 1 creamos nuestra función `main` y un pequeño banner. **No borres ese código**, ¡vamos a construir sobre él!

#### Paso 1: Pedir el nombre del usuario
Justo debajo de los `println` de tu banner de bienvenida, vamos a imprimir una instrucción para el usuario. Usa `print` (sin la terminación `ln`) para que el cursor de la terminal se quede esperando en la misma línea:

```kotlin
print("Por favor, introduce tu nombre: ")
```

#### Paso 2: Capturar el Input
Ahora, vamos a leer lo que el usuario escriba. Para ello usamos la función `readlnOrNull()`.
Agrega esta línea debajo de tu `print`:

```kotlin
// readlnOrNull() devuelve un String nullable (String?) porque la lectura 
// de la terminal podría fallar o interrumpirse inesperadamente.
val input: String? = readlnOrNull()
```

#### Paso 3: Validar la nulabilidad de forma segura
Como `input` es de tipo `String?`, Kotlin no nos dejará usarlo ciegamente. Vamos a usar un bloque `if/else` clásico para validar matemáticamente si el usuario ingresó algo o si nos devolvió un nulo.
Agrega la siguiente lógica:

```kotlin
// Declaramos 'username' como val (Solo Lectura) porque no cambiará en este flujo.
val username: String

// Validamos que input no sea nulo Y que no esté compuesto solo de espacios en blanco
if (input != null && input.isNotBlank()) {
    username = input // ¡Smart Cast en acción! Aquí 'input' ya es un String seguro
} else {
    username = "Invitado" // Nuestro valor por defecto
}
```

#### Paso 4: Saludar al usuario
Finalmente, agreguemos un saludo personalizado utilizando **String Templates** (inyectando la variable con `$`).

```kotlin
println("\n¡Hola, $username! ¿En qué te puedo ayudar hoy?")
```

#### Paso 5: ¡Ejecuta y prueba!
1. Haz clic en el botón verde de **Play** junto a tu función `main`.
2. Cuando la consola te pregunte tu nombre, escríbelo y presiona Enter.
3. Vuelve a ejecutar el programa, pero esta vez simplemente presiona Enter sin escribir nada para comprobar que tu lógica de validación te asigna el nombre "Invitado" y evita un colapso.

¡Felicidades! Has interactuado exitosamente con la I/O (Input/Output) y has protegido tu aplicación de un `NullPointerException`.
